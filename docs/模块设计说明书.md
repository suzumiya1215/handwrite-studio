**一句话概括本文的设计主张**：

> 把产品切成 **「6 个可独立测试的纯逻辑模块」+「1 个界面模块」+「1 个装配层」**。
> 纯逻辑模块一个都不允许 import Qt；界面只做三件事——收参数、调服务、画结果。
> 所有跨模块传的都是**朴素 Python 数据对象**（dataclass / dict / list），不传 Qt 类型，不传文件句柄。

### 1.2 每个模块的一句话职责

| 编号 | 模块 | 一句话职责 | 关键不变量 |
|---|---|---|---|
| **M1** | `base/imageops` | 把一张手写照片变成一堆干净的字形图 | 输出的字形图**背景全透明、前景纯黑、高 128px** |
| **M2** | `base/geometry` | 毫米和像素之间的唯一换算处 | **全项目只有这里做 mm↔px**，别处一律用 mm 存储 |
| **M3** | `services/font_service` | 字形库的读、写、校验、加样本 | 任何时刻 `manifest.characters[x].count == len(files)` |
| **M4** | `services/template_service` | 载入 PDF/图片、按 DPI 渲染成位图、管页 | 渲染出的位图**像素尺寸与 DPI 严格对应** |
| **M5** | `services/grid_service` | 把网格参数算成一堆单元格矩形 | 坐标口径固定为「页面左上角原点，单位 mm」 |
| **M6** | `services/content_service` | 产出「第几行第几列该填什么字」的矩阵 | 输出矩阵形状**恒等于** `(grid.rows, grid.cols)` |
| **M7** | `services/fill_service` | **核心**：把内容矩阵烧进模板位图 | 同一 `seed` + 同一输入 = **逐像素相同**的输出 |
| **M8** | `services/project_service` | `.hwpj` 的打包与解包 | 写入的 `.hwpj` 必须能被自己读回来且语义等价 |
| **M9** | `services/export_service` | 把填充结果写成 PDF / PNG 文件 | 导出 DPI 只在这一层决定，下游不再缩放 |
| **M10** | `ui/*` | 收用户操作、调服务、显示结果 | **不允许出现任何算法**（阈值、坐标、随机数） |
| **M11** | `app.py` | 把上面这些串起来 | 依赖单向：`app.py` 认识所有人，所有人不认识 `app.py` |

## 2. 依赖关系图（谁能 import 谁）

### 2.1 模块依赖有向图

```
                            ┌────────┐
                            │ app.py │
                            └───┬────┘
                ┌───────────────┼───────────────┐
                ▼               ▼               ▼
            ┌───────┐     ┌──────────┐    ┌──────────┐
            │ ui/*  │────▶│ services │───▶│ models   │
            └───────┘     └────┬─────┘    └────┬─────┘
                               │               │
                               ▼               ▼
                          ┌────────────────────────┐
                          │      base/*            │
                          └────────────────────────┘
```

**规则（CI 可检查）**：

| 规则 | 内容 | 违反后果 |
|---|---|---|
| **R1** | `base/` **不得** import `services/`、`models/`、`ui/` | base 出现上层依赖 → 循环导入 |
| **R2** | `models/` **只** import `base/`，**不得** import `services/`、`ui/` | — |
| **R3** | `services/` import `base/` + `models/`，**不得** import `ui/` | 服务层沾上 Qt → 无法单测 |
| **R4** | `ui/` 只 import `services/` 的**公开方法**与 `models/` 的数据类 | 界面里藏算法 → 无法单测 |
| **R5** | **任何文件**不得直接 `import PySide6`（除 `ui/` 与 `main.py`） | — |
| **R6** | 服务之间**不互相 import 对方的内部函数**，只走对方公开方法 | 可用接口替身（fake）测试 |

> R5 是最硬的一条。它保证 **M1~M9 可以在一台没有装 PySide6 的机器上跑测试**。
> 实现手段：CI 里加一条 `grep -r "PySide6" core/ | grep -v "^$" && exit 1`。

### 2.2 服务之间的调用关系（不是依赖，是调用）

服务层内部**平级**，谁也不 import 谁，由 `app.py` 装配、由 `fill_service` 在运行时**接收**其他服务的成果作为参数。

```
  FontService ──┐
                │  FontLibrary
  TemplateService ─┬─▶ TemplatePage ──┐
                   │                  │
  GridService ─────┼─▶ list[CellRect] ┤
                   │                  ├──▶  FillService.render_page(...)  ──▶ PIL.Image
  ContentService ──┼─▶ ContentMatrix ─┤
                   │                  │
  JitterSpec ──────┘──────────────────┘
                                        │
  ExportService  ──┘  拿 PIL.Image 写盘 ──▶ .pdf / .png
```

**关键**：`FillService` **不持有**也不**查找**任何其他服务。它是个纯函数：

```python
render_page(page_bitmap, cells, matrix, font, jitter, seed) -> PIL.Image
```

要什么就传什么。这样它是**最容易测的**——测试时不需要构造整个应用。

### 4.1 M1 · `base/imageops.py` — 图像处理

**职责**：照片 → 干净字形图。也是「框选预览」用的图像来源。

**依赖**：`numpy`、`cv2`、`PIL`、`base/geometry`、`base/errors`

**它不认识**：什么叫「字形库」、什么叫「字符」。它只处理**图像**和**矩形框**。

#### 公开接口

```python
# ── 步骤 1：抠图 ──────────────────────────────────────────
def binarize(
    img: np.ndarray,            # shape (H,W,3) uint8，BGR
    tolerance: int = 29,        # 0~100，UI 上的「容差」滑块
    invert: bool = False,       # 反色（白笔黑纸）
) -> np.ndarray:                # shape (H,W) uint8，前景=255，背景=0
    """灰度 → 阈值 → 形态学去噪。返回**前景为白**的二值图。"""

def deskew(
    binary: np.ndarray,
    angle_deg: float,           # -15 ~ +15，UI 上的「旋转校正」
) -> np.ndarray:
    """按角度旋转二值图，空白补 0。正角度=顺时针。"""

# ── 步骤 2：切分 ──────────────────────────────────────────
def find_boxes(
    binary: np.ndarray,
    min_area_ratio: float = 0.0002,   # 相对整图面积的最小面积
    max_aspect: float = 6.0,          # 高/宽 超过此值判为表格线残留
    row_tolerance_ratio: float = 0.6, # 行聚类时允许的 y 偏差（相对行高）
) -> list[Box]:                       # Box = (x, y, w, h)，已按「先上下、后左右」排序
    """连通域 → 面积/长宽比过滤 → 排序。**这是框字页的自动框选结果。**"""

def merge_nearby_boxes(boxes: list[Box], gap_px: int) -> list[Box]:
    """把水平相邻、间隙小于 gap 的框合并（治「小数点被切成两个点」）。"""

# ── 步骤 3：归一化 ────────────────────────────────────────
def crop_to_content(binary: np.ndarray, box: Box) -> np.ndarray:
    """按 box 裁剪，再收紧到非零像素的外接框。"""

def normalize_glyph(
    src: np.ndarray,            # 原图（可以是彩色）或二值图
    box: Box,
    target_height: int = 128,   # = manifest.glyph_height
    pad_px: int = 2,            # 四边留白，防旋转裁笔画
) -> tuple[Image.Image, tuple[int, int]]:
    """
    裁剪 → 收紧 → 等比缩放到高 target_height → 转 RGBA（前景黑/背景透明）。
    返回 (RGBA 图, (原始宽, 原始高))。第二个值给 manifest.sample_sizes 用。
    """

# ── 步骤 4：形变（填充引擎用） ─────────────────────────────
def scale(img: Image.Image, fx: float, fy: float) -> Image.Image:
def rotate(img: Image.Image, deg: float) -> Image.Image:      # 双线性，expand=True
def slant(img: Image.Image, deg: float) -> Image.Image:       # 错切变换，不是旋转
def dilate_alpha(img: Image.Image, px: float) -> Image.Image:  # 加粗：只膨胀 alpha 通道
def paste_centered(canvas: Image.Image, patch: Image.Image, cx: int, cy: int) -> None:
    """把 patch 以 (cx,cy) 为中心贴到 canvas（原地改），用 alpha 作蒙版。"""

# ── 辅助 ─────────────────────────────────────────────────
def load_image_any(path: str) -> np.ndarray:
    """读图，兼容中文路径（cv2.imread 不支持中文路径，必须用 np.fromfile + imdecode）。"""
```

#### 内部实现要点

**`binarize` 的阈值映射**（与需求文档 §9.3-A 一致）：

```python
thresh = 40 + (tolerance / 100) * 180      # 0→40, 100→220
_, binary = cv2.threshold(gray, thresh, 255, cv2.THRESH_BINARY_INV)
if invert:
    binary = cv2.bitwise_not(binary)
binary = cv2.morphologyEx(binary, cv2.MORPH_OPEN, np.ones((2, 2), np.uint8))
```

**`find_boxes` 的排序**——排序错会让标注全乱：

```python
boxes.sort(key=lambda b: (round(b[1] / row_h_tol), b[0]))
```

先用「y 除以容差取整」聚行，再按 x 排。直接按 `(y, x)` 排会因手写抖动把同一行拆成两行。

**⚠️ 陷阱：小符号被面积阈值误杀**（实施计划 M2 已标注的坑）

`.` 和 `,` 的像素面积远小于数字。固定的 `min_area` 会把它当噪点删掉。
**正确做法**：`min_area` 按**预期字符高度**动态算——

```python
# 先用大阈值跑一遍，取所有框中位高度作为「预期字高」
median_h = statistics.median(b[3] for b in raw_boxes)
min_area = (median_h * 0.12) ** 2      # 字高的 12% 见方，约能兜住小数点
```

**⚠️ 陷阱：中文路径**

`cv2.imread("D:/桌面/我的字.jpg")` 返回 `None`，**不报错**。必须：

```python
buf = np.fromfile(path, dtype=np.uint8)      # fromfile 支持中文路径
img = cv2.imdecode(buf, cv2.IMREAD_COLOR)
```

### 4.2 M2 · `base/geometry.py` — 坐标与换算

**职责**：**全项目唯一的 mm↔px 换算处**。以及矩形运算、旋转外接框。

**为什么单独成模块**：需求文档定了「mm 为存储单位，px 只在最终贴图时 round 一次」。
如果各模块自己写 `* dpi / 25.4`，会出现 `25.4` 这个常数散落十几处、精度口径不一致、行距累积误差。
集中到这一个文件，改口径只需改一处。

#### 公开接口

```python
MM_PER_INCH = 25.4

def mm_to_px(mm: float, dpi: int) -> float:
    """mm → px。**返回 float，不取整**（重要：中间取整会累积误差）。"""

def px_to_mm(px: float, dpi: int) -> float:
    """px → mm。"""

def mm_to_px_r(mm: float, dpi: int) -> int:
    """带四舍五入的版本，**只在最终贴图/画框时用**。"""

def rect_mm_to_px(rect: Rect, dpi: int) -> tuple[int, int, int, int]:
    """(left, top, right, bottom) mm → px 整数四元组，统一在这里 round。"""

# ── 几何运算 ──────────────────────────────────────────────
@dataclass(frozen=True)
class Rect:
    left: float; top: float; right: float; bottom: float
    @property
    def w(self) -> float: ...
    @property
    def h(self) -> float: ...
    @property
    def cx(self) -> float: ...
    @property
    def cy(self) -> float: ...
    def inset(self, d: float) -> "Rect": ...
    def intersect(self, other: "Rect") -> "Rect | None": ...

def rotated_bounds(w: float, h: float, deg: float) -> tuple[float, float]:
    """旋转 deg 度后的外接框尺寸。用于给旋转后的字形预留空间。"""

def fit_scale(src_w: float, src_h: float, box_w: float, box_h: float) -> float:
    """等比缩放到刚好放进 box 的倍数（取 min）。排版时用。"""
```

#### 陷阱

**⚠️ 不要在中间步骤 round**。填充一行 24 个格子时，如果每格都 `int()`，
误差会以每格最多 0.5px 累积，到第 24 格就偏 12px——**肉眼可见的行距不均**。
正确做法：全程记 mm 或 float px，**只在 `Image.paste` 的前一步**用 `mm_to_px_r`。

### 4.3 M3 · `services/font_service.py` — 字形库

**职责**：`.hwfont` 的加载、保存、校验、增删样本。以及**驱动采集流程**（调 M1 的三步）。

**依赖**：`base/imageops`、`base/charset`、`base/paths`、`base/errors`、`models/glyph`

#### 输入

| 方法 | 输入 |
|---|---|
| `load` | 字形库目录路径（或 `.hwfont` 压缩包路径） |
| `save` | `FontLibrary` 对象 + 目标路径 |
| `extract_step1` | 原图路径 + 容差 + 反色 + 旋转角 |
| `extract_step2` | 二值图 + 人工增删的框列表 |
| `extract_step3` | 框列表 + 每个框对应的字符标注 |
| `add_samples` | `FontLibrary` + 字符 + 新样本列表 |

#### 输出

| 方法 | 输出 |
|---|---|
| `load` | `FontLibrary` |
| `save` | `None`（写盘） |
| `extract_step1` | `(binary_img, list[Box])` |
| `extract_step2` | `list[Box]`（用户编辑后） |
| `extract_step3` | `FontLibrary`（新建的） |
| `add_samples` | `FontLibrary`（新对象，不改原对象） |

#### 公开接口


#### 数据流（采集向导三步）

```
原图路径 + 容差/反色/旋转
        │
        ▼  extract_step1
  (二值图, 自动框列表)  ──▶ 界面画框字页
        │                         │ 用户右键删框 / 拖拽补框
        ▼  extract_step2            ▼
  (编辑后的框列表)  ────────────────┘
        │
        ▼  extract_step3（用户给每个框标了字符）
  FontLibrary  ──▶ save()  ──▶ .hwfont 落到用户数据目录
```

**为什么三步分开暴露**：界面需要在第 2 步停下来让用户框选、在第 3 步停下来让用户标注。
如果合成一个 `extract_all()`，中间结果就没地方放（塞进服务里就成了有状态服务，无法重入）。

#### 陷阱

**⚠️ `manifest.characters[x].count` 必须等于 `files` 长度**
这是 §1.2 定的不变量。`add_samples` / `remove_sample` 后必须同步更新，否则加载时校验失败。

**⚠️ 中文路径 + 中文文件名**
`.hwfont` 内部的文件名一律用 **ASCII**（`001.png`），字符目录名用 `comma`/`dot`（见 §4.4 映射表）。
**不要在 zip 里放中文文件名**——不同解压工具编码处理不一致，会踩坑。

**⚠️ 原子写**

```python
tmp = path + ".tmp"
shutil.make_archive(tmp, "zip", root_dir=staging)
os.replace(tmp_zip, final_zip)     # 同盘 rename 是原子的
```

### 4.4 M4 · `services/template_service.py` — 模板管理

**职责**：载入 PDF / 图片，按指定 DPI 渲染成位图，管页数、页尺寸。

**依赖**：`fitz`(PyMuPDF)、`PIL`、`base/geometry`、`base/errors`、`models/template`

#### 公开接口

```python
class TemplateService:
    def open(self, path: str) -> TemplateDoc: ...
        """载入 PDF / PNG / JPG。PDF 走 fitz，图片包成单页 doc。"""

    def render_page(self, doc: TemplateDoc, index: int, dpi: int) -> Image.Image: ...
        """渲染第 index 页为 RGB 位图。**位图像素尺寸 = 页 mm 尺寸 × dpi / 25.4**。"""

    def preview_page(self, doc: TemplateDoc, index: int) -> Image.Image: ...
        """按 doc.preview_dpi（默认 150）渲染，给界面看。"""

    def page_geometry(self, doc: TemplateDoc, index: int) -> PageGeometry: ...
        """返回该页的 width_mm / height_mm / width_px(dpi=300) 等，供 M5 算网格。"""

    def close(self, doc: TemplateDoc) -> None: ...
        """释放 fitz 句柄。**必须调**，否则文件被锁住删不掉。"""
```

#### 关键设计：双 DPI 口径

| 用途 | DPI | 理由 |
|---|---|---|
| 界面预览 | **150** | 清晰度够，渲染快（A4 约 1240×1754） |
| 正式导出 | **300** | 打印标准，字形锐利 |

**填充引擎接收的是已渲染好的位图**，自己不知道 DPI。它只在这张图上按像素干活。
这样**预览和导出可以走完全相同的填充代码**，只是喂进去的位图尺寸不同——
预览看到的抖动比例，导出后**严格一致**（因为抖动都以「单元格尺寸的比例」表达，不是绝对像素）。

`PreviewCache`：界面滚动预览时反复要同一页，用 `dict[(page_idx, dpi) -> Image]` 缓存，
超过 3 页淘汰最旧的（A4@150dpi 约 6MB，3 页 18MB，可接受）。

#### 陷阱

**⚠️ `get_pixmap` 的 alpha**
PDF 有透明背景。渲染时指定 `alpha=False` 得到 RGB，否则 alpha 通道会和字形蒙版打架。

**⚠️ 坐标系翻转**
`page.rect` 原点在左上（与图像一致），但 PDF 内部原点在左下。
用 `fitz` 的 `insert_image` 写回时它会自己处理，**不要手动翻转 y**。

**⚠️ 中文字体嵌入**
如果模板 PDF 里用了系统没有的字体，渲染出来会是方框。这是模板本身的问题，
程序应在载入时**检测并提示**：「该 PDF 有 N 处字体缺失，预览可能与原件不同」。

#### `CellRect` 的坐标口径（**照抄数据格式规范 §2.3，不得改**）

```
left   = start_x_mm + col * col_width_mm
top    = start_y_mm + row * row_height_mm
right  = left + col_width_mm
bottom = top  + row_height_mm

内容区（去内边距）：
c_left = left + cell_padding_mm   ... 依此类推
```

**`CellRect` 同时存 mm 和 px**：

```python
@dataclass(frozen=True)
class CellRect:
    row: int
    col: int
    rect_mm: Rect                       # 权威值
    content_mm: Rect                    # 去内边距后
    rect_px: tuple[int,int,int,int]     # 按传入 dpi 算好的，省得下游重复算
    content_px: tuple[int,int,int,int]
```

**为什么提前算 px**：填充引擎每格都要用 px，提前算一次（在 `build_cells` 里，已知 dpi）
比每格再调一次换算函数更快，也避免下游漏传 dpi。

#### 陷阱

**⚠️ `active_cols` 为空数组 = 全部列**
这是数据格式规范定的语义。判空时要写 `spec.active_cols or range(spec.cols)`，
不能写成 `if spec.active_cols: ...`（空数组 falsy，会走进错误分支）。

**⚠️ 行号起点**
`row_index_start` 只影响**界面显示的行号**，不影响 `CellRect.row`（恒为 0-based）。
两者别混。

#### `RandomSpec` 的随机规则

支持三种类型（对应数据格式规范 §2.4.1 的 `random.type`）：

| type | 生成规则 | 例 |
|---|---|---|
| `integer` | 整数，范围 `[min, max]`，位数 `[length_min, length_max]` | 体温 36~37 |
| `decimal` | 定点小数，`decimals` 位 | 36.5 |
| `pick` | 从给定候选列表随机抽 | 从 `["优","良","中"]` 抽 |

**统一约束**：生成结果里若出现非 `CHARSET_V1` 字符（比如候选列表里有汉字），
**不在这里过滤**——留给 `FillService` 统一处理（跳 + 计数）。
理由：内容层过滤会让界面拿到的矩阵和实际填的不一致，用户会困惑「我明明填了怎么变空了」。
**提示的责任在前端**：`missing_chars()` 的结果驱动界面黄底提示。

#### 陷阱

**⚠️ 随机性必须「可复现」和「逐格独立」同时满足**
需求文档定的方案：**每格独立派生 rng**

```python
rng = np.random.default_rng((seed or 0) + row * 1000 + col)
```

这样：
- 同一 seed → 同一矩阵（可复现）
- 改第 5 行第 3 格 → 第 4 行第 2 格**不受影响**（独立性）

**不能**用一个全局 rng 顺序生成——那样改一格会让后面全变，用户会抓狂。

**⚠️ `row * 1000 + col` 的溢出**
`cols` 上限 50、`rows` 上限 200，`row*1000+col` 最大 200000，远小于 int64，安全。

#### 四层抖动的**执行顺序**（**不可乱，这是产品精髓**）

```
对单元格 (row, col)：

  ┌─ 第 1 层：单字形变 ──────────────────────────────┐
  │  ① 从该字符的样本里随机取一个（按 sample_sizes 匹配宽高比）│
  │  ② 缩放 scale  ∈ [scale_min, scale_max]           │
  │  ③ 拉伸 stretch_x / stretch_y                     │
  │  ④ 倾斜 slant（错切，不是旋转）                    │
  │  ⑤ 加粗 dilate_alpha(bold_px)                     │
  └───────────────────────────────────────────────────┘
                          ▼
  ┌─ 第 2 层：单字位置 ──────────────────────────────┐
  │  整串字在格内水平排布，逐字加 offset_x/offset_y    │
  │  字间距加 spacing 抖动                            │
  │  → 每字算出 (cx, cy) 后贴到**格子的临时图层**上     │
  └───────────────────────────────────────────────────┘
                          ▼
  ┌─ 第 3 层：整格变换 ──────────────────────────────┐
  │  ★ 把临时图层**整体**平移 offset_x/offset_y       │
  │  ★ 再把临时图层**整体**旋转 rotate_deg            │
  │  ★ 最后把这个图层贴到大画布上                      │
  └───────────────────────────────────────────────────┘
                          ▼
  ┌─ 第 4 层：小数点 ────────────────────────────────┐
  │  若该格含 '.' 或 ','，对每个符号单独再抖一次       │
  │  （位置 offset + 大小 scale，用 dot 组参数）       │
  └───────────────────────────────────────────────────┘
```

**⚠️⚠️ 第 3 层绝不可以逐字各转**
这是最容易写错的地方。如果对每个字单独做「整格旋转」，字会各自绕自己的中心转，
结果是**每个字歪向不同方向**，像散了架的活字印刷。
正确做法：**先把整格的字符合成到一张和格子等大的透明图层，再对这张图层整体旋转**，
字与字的相对位置才不会被破坏。

#### 单格渲染细节（`render_cell`）

```python
def render_cell(self, cell, text, font, jitter, rng):
    if not text:
        return None

    cw = cell.content_px[2] - cell.content_px[0]
    ch = cell.content_px[3] - cell.content_px[1]

    # 1. 取每个字的字形并做单字形变
    glyphs = []
    for chx in text:
        if chx not in font.characters:
            continue                        # 交给上层计数（见下）
        sample = self._pick_sample(font, chx, rng)
        g = self._shape_glyph(sample, jitter.char_shape, rng)
        glyphs.append((chx, g))

    if not glyphs:
        return None

    # 2. 排版：本格的可用高度 = 内容区高度 × 一个整体缩放系数
    #    先算出所有字形的总宽（含间距），再等比缩放到刚好放进格子
    ...

    # 3. 逐个贴到格子图层（含第 2 层单字位置抖动）
    layer = Image.new("RGBA", (cw, ch), (0, 0, 0, 0))
    x_cur = 0
    for chx, g in glyphs:
        dx = (rng.random() - 0.5) * 2 * jitter.char_pos.offset_x * cw
        dy = (rng.random() - 0.5) * 2 * jitter.char_pos.offset_y * ch
        paste_centered(layer, g, int(x_cur + dx), int(ch / 2 + dy))
        x_cur += g.width + spacing

    # 4. 第 3 层：整格平移 + 整格旋转（对 layer 整体操作！）
    ...

    return layer
```

**「字数自适应缩字号」的算法**：

```
1. 每个字形先归一化到统一高度 H0 = 内容区高度 × 0.72（这个系数是观感调出来的）
2. 算总宽 W = Σ(glyph.width) + spacing × (n-1)
3. 若 W > 内容区宽 → 整体等比缩小 k = 内容区宽 / W，所有字形乘 k
4. 重新排布
```

这样「单元格里是 2 位数还是 4 位数」会自动换字号，**不会溢出格子**。
与界面原型里 `.content` 的预览逻辑是同一条规则（原型里是 `fs = min(h*0.60, w*0.90/len)`）。

#### 跳过的字符怎么计数

```python
# 在 render_page 里维护
skipped: Counter[str] = Counter()
for cell in cells:
    text = matrix.at(cell.row, cell.col)
    for chx in text:
        if chx not in font.characters:
            skipped[chx] += 1
```

**注意**：`render_cell` 内部按字符查表，`render_page` 外层也查一遍用于计数——
两处判据必须**同一个**（都用 `font.characters`），否则计数和实际不符。
建议抽成 `font.has(chx)` 方法，两边都调它。

#### 陷阱汇总

| 陷阱 | 症状 | 正确做法 |
|---|---|---|
| 整格旋转逐字做 | 字歪向各方向 | 先合成图层再整体转 |
| 中间步骤 round | 行距累积偏移 | 全程 float，最后 round |
| 用全局 rng | 改一格全变 | 每格 `default_rng(seed+row*1000+col)` |
| 直接改入参图 | 预览被污染 | `page_bitmap.copy()` 再画 |
| 旋转后超出格子没裁 | 字压到邻格 | 图层尺寸=格子尺寸，天然裁掉 |
| 倾斜用 rotate 实现 | 字变胖/变瘦错 | 用 `Image.transform(AFFINE)` 错切矩阵 |

```python
        """【v1.1 预留】把字形库跟着项目一起打包。"""

    def is_dirty(self, project: Project) -> bool: ...
```

#### `Project` 与加载的容错策略

加载时**分三级**处理问题：

| 级别 | 情形 | 处理 |
|---|---|---|
| **致命** | zip 损坏 / `project.json` 缺 `format` 字段 / `version` 高于程序支持 | 抛异常，拒绝打开 |
| **可恢复** | 引用的字形库 id 找不到 | 打开项目，`unresolved_font=True`，界面提示「请重新选择字形库」 |
| **警告** | 某个 jitter 值越界 / `rows` 与实际内容行数不符 | 箝位/补齐，`warnings` 列表带回界面 |

**为什么不把「找不到字形库」当致命错**：用户可能把字形库挪走了、或换电脑了。
直接拒绝打开 = 用户的项目参数全白设。应该让他打开、重新指一个库，**参数保住**。

#### 陷阱

**⚠️ `template/template.pdf` 必须一起打包**
不能只存原文件路径。用户原文件一移动，项目就打不开了。
`.hwpj` 里 embed 一份模板副本（PDF 通常 100KB~2MB，可接受）。

**⚠️ 自动保存的频率**
不能每次参数变动都写盘（拖动滑块会卡）。策略：
- 参数改动后 **30 秒防抖**写一次
- 关键操作（导出、切换页）**立刻**写一次
- 崩溃恢复：启动时检测 autosave 比最近手动保存新，提示「上次编辑未正常保存，是否恢复？」

### 4.9 M9 · `services/export_service.py` — 导出

**职责**：把填充好的页图写成 PDF / PNG。

**依赖**：`fitz`、`PIL`、`base/geometry`、`base/paths`、`base/errors`

#### 公开接口

```python
class ExportService:
    def render_all_pages(
        self,
        project: Project,
        template: TemplateDoc,
        font: FontLibrary,
        fill: FillService,
        on_progress: Callable[[int, int], None] | None = None,
        cancel_flag: threading.Event | None = None,
    ) -> list[tuple[int, Image.Image]]:
        """逐页渲染。**这是导出流程的编排者**——它依次调 template/fill。"""

    def export_pdf(
        self, pages: list[tuple[int, Image.Image]],
        template: TemplateDoc, out_path: str, dpi: int = 300,
    ) -> str: ...

    def export_png(
        self, pages: list[tuple[int, Image.Image]],
        out_dir: str, dpi: int = 300, name_pattern: str = "第{page}页.png",
    ) -> list[str]: ...

    def suggest_output_path(self, project: Project, kind: str) -> str: ...
        """默认存到源 PDF 同目录，名如「晨午检表_手写版.pdf」，重名自动加 (1)。"""
```

#### 为什么 `render_all_pages` 放在 ExportService 而不是 FillService

`FillService` 是**纯函数**（一页进一页出），不该知道「项目」「模板对象」「进度回调」。
编排「对每一页：渲染模板 → 算网格 → 取内容 → 填充」是**应用逻辑**，属于 ExportService。

这也让 `FillService` 保持可单测——测它不需要 Project 对象。

#### 导出流程

```
for page_idx in selected_pages:
    ① template.render_page(doc, page_idx, dpi=300)        → 位图 base
    ② grid.build_cells(geometry, spec)                     → cells
    ③ matrix = content（随机模式下用同一 seed 重新生成，
                          保证预览和导出内容一致）
    ④ fill.render_page(base, cells, matrix, font, jitter, seed)  → 填好的图
    ⑤ 收集 (page_idx, filled)

→ export_pdf: 用 fitz 建新文档，逐页 insert_image
```

**⚠️ 预览与导出必须用同一 seed**
否则用户预览看到 36.5，导出变成 37.2，会以为程序坏了。
`Project.seed` 在随机模式下**必须有值**（首次生成时确定并写回 project.json）。

### 4.10 M10 · `ui/*` — 界面层

**职责**：收参数、调服务、画结果。

**铁律**：**界面里不允许出现算法**。

#### 界面能做什么 / 不能做什么

| ✅ 可以做 | ❌ 不可以做 |
|---|---|
| 读控件值，组成 `GridSpec` / `JitterSpec` | 自己算单元格坐标 |
| 调 `service.xxx()` | 自己在图上画字 |

## 6. 跨模块契约（必须共同遵守）

### 6.1 单位契约

| 契约 | 内容 |
|---|---|
| **C1** | 所有**存储**的长度用 **mm**（网格参数、页面尺寸） |
| **C2** | 所有**计算**中途用 **float**，不做中间取整 |
| **C3** | **唯一**的 mm→px 转换点是 `geometry.mm_to_px / mm_to_px_r` |
| **C4** | 图像相关的 px 值在 `CellRect` 里**预先算好**，下游直接用 |

### 6.2 随机性契约

| 契约 | 内容 |
|---|---|
| **C5** | 任何随机都走 `np.random.default_rng(seed)`，**不用** `random` 模块、不用全局 `np.random` |
| **C6** | 格子级随机的派生子种子固定为 `seed + row*1000 + col` |
| **C7** | `seed=None` 表示真随机；一旦需要「预览=导出」，**必须**把它固化成整数存进 project |
| **C8** | 同一 seed + 同一输入 → `render_page` 输出**逐像素相同**（用 `ImageChops.difference` 可验证） |

### 6.3 字符集契约

| 契约 | 内容 |
|---|---|
| **C9** | 权威字符集只有一处：`charset.CHARSET_V1`（12 个） |
| **C10** | 超出字符集的内容**不报错、不静默丢弃**，走 `skipped_chars` 计数 + 界面提示 |
| **C11** | 字符 → 目录名的映射只有 `charset.char_to_dirname()` 一个实现，禁止别处硬编码 `"comma"` |

### 6.4 图像契约

| 契约 | 内容 |
|---|---|
| **C12** | 字形图恒为：**RGBA**、前景纯黑、背景 alpha=0、高 `glyph_height` |
| **C13** | 服务层的方法**不得修改入参图像**，需要改的先 `.copy()` |
| **C14** | 界面拿到 `PIL.Image` 后负责转 `QPixmap`，服务层不认识 Qt |

### 6.5 错误契约

| 契约 | 内容 |
|---|---|
| **C15** | 所有自定义异常继承 `core/base/errors.AppError`，且**必须带 `user_message`（中文）** |
| **C16** | 服务层**不弹窗、不打印**，只抛异常或返回带 `warnings` 的结果；**展示是界面的责任** |
| **C17** | 可恢复问题（缺字形、参数越界）走 `warnings` 列表，**不抛异常** |

## 7. 错误传播链路

```
                      ┌──────────────────────────────┐
                      │ 底层（base）抛 AppError        │
                      │ 例：FontCorruptedError        │
                      │     user_message="字形库损坏…" │
                      └──────────────┬───────────────┘
                                     ▼
                      ┌──────────────────────────────┐
                      │ 服务层：不吞、不包装无谓的层    │
                      │ 能就地降级的降级（写 warnings）│
                      │ 不能降级的原样上抛             │
                      └──────────────┬───────────────┘
                                     ▼
                      ┌──────────────────────────────┐
                      │ 界面：try/except AppError     │
                      │   → QMessageBox 显示           │
                      │     e.user_message（中文）     │
                      │   → 写日志（含 traceback）      │
                      └──────────────────────────────┘
```

**异常类型清单**（`core/base/errors.py`）：

| 异常 | user_message 示例 | 触发场景 |
|---|---|---|
| `AppError` | — | 基类 |
| `FontNotFoundError` | 「找不到字形库『我的字迹』，请重新选择」 | 项目引用的库丢了 |
| `FontCorruptedError` | 「字形库文件已损坏（缺少 manifest.json）」 | 校验失败 |
| `TemplateUnsupportedError` | 「不支持的文件格式：xxx，请用 PDF 或图片」 | 载入了 exe |
| `TemplatePasswordError` | 「该 PDF 有密码保护，无法打开」 | 加密 PDF |
| `GridOutOfBoundsError` | 「网格超出页面范围（右边超出 3.2mm）」 | 参数不合理 |
| `ContentEmptyError` | 「没有任何内容可以填充」 | 矩阵全空 |
| `ExportFailedError` | 「导出失败：目标文件被其他程序占用」 | 文件被 WPS 打开 |
| `DiskFullError` | 「磁盘空间不足，请清理后重试」 | 写盘失败 |

**降级而非报错的情况**（走 warnings）：

| 情况 | 处理 |
|---|---|
| 内容里有字形库没有的字符 | 跳过该字，`skipped_chars` 计数，状态栏提示 |
| jitter 某值越界 | 箝位到合法区间，加一条 warning |
| 内容行数多于 `grid.rows` | 截断，加 warning「有 3 行内容超出网格，已忽略」 |
| 内容行数少于 `grid.rows` | 补空行，**不警告**（正常情况） |
| 找不到项目引用的字形库 | `unresolved_font=True`，界面提示重新选择 |

## 8. 测试接缝（模块可测性设计）

**能被单独测的函数 = 有明确「输入→输出」且不依赖全局状态的函数。**

| 模块 | 最该测的接口 | 怎么测（不需要界面、不需要真实文件） |
|---|---|---|
| M1 imageops | `binarize` / `find_boxes` / `normalize_glyph` | 造一张合成图（画几个黑矩形）→ 断言框数量和位置 |
| M2 geometry | `mm_to_px` / `rotated_bounds` | 直接断言数值（含边界值、0、负数） |
| M3 font_service | `extract_step3` / `add_samples` | 用 `tmp_path` 造目录，断言 manifest 字段 |
| M4 template_service | `render_page` 的尺寸 | 造一个小 PDF，断言 `size_px(300)` 等于预期 |
| M5 grid_service | `build_cells` / `cell_at` | 给定 spec 断言第一格和最后一格的矩形 |
| M6 content_service | `parse_paste` / `generate_random` | 断言形状、可复现性（两次同 seed 相等） |
| **M7 fill_service** | **`render_cell` / `render_page`** | **造一个假的 FontLibrary（程序化画 12 个字符）→ 断言输出尺寸、非空像素比例、同 seed 逐像素一致** |
| M8 project_service | `save` → `load` 往返 | 断言往返后语义等价（不含时间戳） |
| M9 export_service | `export_pdf` | 断言输出文件存在、页数正确、能被 fitz 读回 |
