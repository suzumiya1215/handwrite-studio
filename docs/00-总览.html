1这个项目要做什么

一句话说清楚，方便给不参与技术的人看。
基层单位、学校每天要手写大量表格——晨午检表、点名册、签到表。一张 24 行 × 10 列的表格， 手写一遍要 20 分钟以上，还容易抄错。
这个工具让用户拍几张自己写的字，程序把字形采集下来，之后自动把手写字迹填进空白表格， 导出 PDF 直接打印。20 分钟 → 30 秒。

关键设计：让"像手写"这件事可控。同一个字在表格里出现 20 次，如果长得一模一样，一眼就看出是机器填的。 所以每个字都要有位置偏移、旋转、大小变化、拉伸、倾斜。这些参数分四层给用户调，同时预设「轻微 / 自然 / 明显」三档， 不懂参数的人点一下就行。

3我们比参考产品多做了什么

参考产品售价 ¥5，思路很好，但有几个明显的短板。
参考产品 · 手写数字生成器
  • 只能填 0-9 十个数字，小数点都填不了
  • 参数全是数字输入框，没有预设
  • 没有撤销，点错了只能重来
  • 不能保存多套字形
  • 每次生成结果都不一样，无法复现
  • 要付费 ¥5
本项目
  • 数字 + 逗号 + 句点，共 12 个字符（覆盖体检表、成绩表）
  • 非技术用户也能上手，全中文提示
  • 三档预设 + 四层细调，随需切换
  • 录入和框字支持撤销 / 恢复
  • 支持多套字形库，随时切换
  • 可固定随机种子，同参数同结果
  • 免费开源，本地运行
⚖️
合规声明：本项目与「手写数字生成器」没有任何代码层面的关系， 只借鉴其公开的产品思路与交互范式。目标是做一个功能更全的免费等效工具， 供本人及本单位内部合规使用。严禁用于伪造签名、伪造他人笔迹等违法用途。

4五个设计决定（已全部拍板）

这五条定了，整个方案就能往下走。前三条是 10-09 定的，后两条是本次补充确认的。
🖥

做成什么形态？

已定：Python 桌面程序

Windows 上的应用程序。图像处理与 PDF 生态在 Python 里最成熟， 配一个安装包，用户不需要装任何环境。

📷

字形从哪来？

已定：上传手写照片

用户在白纸上写好、拍照上传，程序自动抠背景、切分单字、逐个打标签。 这样出来的是用户自己的字，不是字库里的通用手写体。

👥

给谁用？

已定：非技术用户

不会命令行、不懂路径、看到英文报错就慌。所以：界面全中文、每步能返回、 危险操作二次确认、宁可多几步也不能报错。

🔢

要采多少种字符？

本次定案：恰好 12 个

只做 数字 0-9 加 逗号 句点。不含字母、不含中文标点。
好处很实际：拍 2 张照片、5 分钟就采完，采集界面也简单得多—— 字符键盘只有一排 12 个键。

📦

怎么交到用户手上？

本次定案：做安装包

做成标准的 Windows 安装程序：双击下一步装好、自动建桌面图标、 能从控制面板卸载、双击字形库文件直接打开。
需要 额外装 Inno Setup 并把打包列入正式交付范围。

6界面长什么样

详细原型见 界面原型.html（可在浏览器直接打开，四个屏可切换）。
①

首页

三张大卡片：新建字形库 / 我的字形库 / 打开项目。 首次使用时第一张最突出；已有字形库则第二张高亮。用户不需要思考"先干什么"。

②

主工作台

左边参数面板、右边实时预览。参数按五个可折叠分组排列， 预览图上直接叠加网格线——拖数字就能看见格子动。

③

字形采集向导

顶部步骤条，三步走：抠图（容差滑块 + 实时对比）→ 框字（自动框选，右键删、拖拽补）→ 标注（一排 12 键的字符键盘，批量打标签）。

④

手动录入弹窗

行 × 列 的表格编辑器，支持从 Excel 直接粘贴。 没有采集到字形的字符会黄底提示"将跳过"，不会静默丢掉。

7技术方案（一句话版）

具体选型理由见《需求文档.md》§9。
层选型为什么
界面PySide6（Qt） 原生控件质感好；图形视图框架天生适合做"缩放预览 + 图上编辑"
图像处理OpenCV + Pillow 抠图、切分、旋转缩放，都是成熟操作
PDFPyMuPDF 渲染快、能直接在原页上贴图，保留模板的矢量内容
打包PyInstaller + Inno Setup 先打出程序目录（启动快），再用 Inno Setup 做成带向导的安装包。 不用单文件模式——每次启动要解压 200MB，首启要等十几秒
架构内核与界面分离 填充引擎是纯函数、不依赖界面，可以独立测试；这是控制技术风险的关键

填充引擎的四个动作（核心逻辑）

对表格里每一个要填的格子，依次做四件事——顺序不能乱：

① 单字形变

从字形库随机挑一个"3"，把它缩放、拉伸、旋转、加粗一点 ——所以同一个"3"每次长得都不太一样。

② 单字位置

一个字一个字地平移到位置上，左右上下微错位，字间距也不均匀 ——这是手写最明显的特征。

③ 整格变换

把这一格里的所有字当作一个整体，一起平移、一起转个角度。 所以要先把字合成到一张透明图层上再转。

④ 小数点

小数点这类小符号单独处理，位置和大小有自己的一套随机值， 否则会显得太规整。

8怎么一步步做出来

每个阶段结束都必须有「能双击运行、能看见结果」的产物。
M1 · 骨架能跑 基础

窗口打开 → 首页三卡片 → 能跳到子页。配置、日志、异常兜底就位。

M2 · 字形采集全通 最重

拿一张实拍照片走完三步，导出一个字形库文件，能重新载入。 图像处理 + 最复杂的交互控件都在这里。

M3 · 填充内核 风险最高

命令行跑通：输入模板 + 内容 + 参数 + 字形库 → 输出一张填好的图。 在此之前不写任何界面代码。

M4 · 主工作台 核心体验

参数面板 + 实时预览 + 网格可视化。改参数 300ms 内看见变化。

M5 · 内容与导出 闭环

手动录入、随机生成、多页 PDF 导出、进度条与取消。 到这里功能已经完整了。

M6 · 项目与打磨 易用性

项目保存 / 加载、自动保存防丢、帮助页、首次运行引导。

M7 · 打包与安装包 正式交付

程序目录 + Inno Setup 安装包 + 一页纸使用说明。 必须在没装 Python 的干净机器上实测安装包——本地开发机测不出缺 DLL 的问题。

🎯
整个计划里最重要的一条纪律：M3 内核跑通之前，不写 Qt 界面代码。 填充引擎是唯一有技术风险的部分——界面写得再漂亮，内核不对就是全白干。

9怎么算做成功了

除了功能清单逐条打勾，还有一条"人肉验收"标准。
✓

功能验收（可测）

· 用手机拍的 A4 照片走完采集，导出字形库不报错
· 24×10 表格填充 + 多页导出，20 页 300DPI 在 30 秒内完成
· 同种子两次生成结果完全一致
· 载入损坏文件时弹中文提示而不是崩溃
· 模板放在含中文和空格的路径下也能正常打开

👀

人肉验收（最重要）

把生成的 PDF 打印出来，和真人手写的同类表格并排放在桌上， 让一位不知情的同事看 5 秒，问："哪张是手写的？"

→ 他不能一眼指出来。

如果一眼看穿，说明抖动不足或样本太单一，回去调参数、补样本。

#问题说明
Q1 工具叫什么名字？
建议尽早定		 暂定「手写字迹填充器」。这个名字会出现在桌面快捷方式、开始菜单、安装程序标题、控制面板卸载列表里， 定下来之后改动要重新打包，成本较高。
备选：手写表格生成器 / 我的字迹填表 / 手写填表助手
Q2 要不要支持汉字？
目前按不做处理		 v1 明确不做。但如果实际用起来发现「填姓名列」的需求压过了「填数值列」， 就要换技术路线（整幅手写页切分 + 按字检索），是另一个量级的产品。
现状：遇到不支持的字符会在界面上明确提示「将跳过」，不会静默丢弃。
Q3 要不要深色模式 / 开机自启？ 都建议 v1 不做。深色模式放 v1.1；开机自启对本工具没意义—— 它是「要用的时候才打开」的类型，常驻只会占内存。
